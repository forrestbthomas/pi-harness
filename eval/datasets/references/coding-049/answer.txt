pi-run fails fast: it resolves the key env var for the explicitly selected provider (DEEPSEEK_API_KEY), finds no value, and aborts with a "no DEEPSEEK_API_KEY available" error and exit code 3 (missing key) — the request never runs. It does not fall back to OpenAI: --provider explicitly selects the routing entry, and silently switching providers would change which key and model are used, so a missing key is a hard error rather than a fallback.
