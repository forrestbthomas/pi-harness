## Long-term Knowledge

### Architecture

<!-- lore:019fc866-ca79-76d1-ac67-14295ec14825 -->
* **pi --offline + NODE\_OPTIONS ipv4first (dead pi.dev route)**: Every spawned pi process gets NODE\_OPTIONS overwritten to --dns-result-order=ipv4first (pre-existing value is DISCARDED, not appended — appending re-introduces the dead IPv6 route), and chat/print add --offline, because the pi.dev model-catalog endpoint intermittently freezes. Offline-by-default with stored catalogs chosen over live fetch; removing --offline or appending to NODE\_OPTIONS re-introduces startup hangs.

<!-- lore:019fc866-ca53-7f3d-aa95-387762e86558 -->
* **providers.json: stdlib-only JSON provider table**: pi-run provider routing is data-driven from root providers.json, with a complete embedded 7-provider fallback (openai, openrouter, deepseek, anthropic, gemini, groq, local/Ollama). Chose stdlib-only JSON over YAML because Go has no standard YAML parser and the project forbids external Go dependencies; LoadProviders keeps a future format swap possible. init() uses loadActiveProviders(repoRoot()): explicit PI\_RUN\_PROVIDERS\_FILE read/parse errors and malformed repository files warn with path/reason before falling back, while a missing default repository file remains silent for released binaries. The CLI lists configured providers and supports adding/removing providers without recompilation.
