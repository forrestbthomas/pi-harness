## Long-term Knowledge

### Architecture

<!-- lore:019fc866-ca79-76d1-ac67-14295ec14825 -->
* **pi --offline + NODE\_OPTIONS ipv4first (dead pi.dev route)**: Every spawned pi process gets NODE\_OPTIONS overwritten to --dns-result-order=ipv4first (pre-existing value is DISCARDED, not appended — appending re-introduces the dead IPv6 route), and chat/print add --offline, because the pi.dev model-catalog endpoint intermittently accepts TLS but never responds over IPv6 or IPv4. Chose offline-by-default using stored model catalogs over live fetch; pi-run setup is the explicit online path and retries the catalog refresh 3× then warns instead of failing. Removing --offline or appending to NODE\_OPTIONS re-introduces startup hangs.

<!-- lore:019fc866-ca53-7f3d-aa95-387762e86558 -->
* **providers.json: stdlib-only JSON provider table**: pi-run provider routing is data-driven from providers.json at repo root; 7 defaults: openai, openrouter, deepseek, anthropic, gemini, groq, and local (Ollama-compatible baseURL http://localhost:11434/v1). Chose JSON over the spec's YAML because Go stdlib has no YAML parser and the project constraint is zero external Go deps (no go.sum); LoadProviders(path) keeps a YAML swap-in possible. internal/cli/providers.go init() loads providers.json via repoRoot() and silently falls back to the original 3 defaults if missing. \`pi-run providers\` lists Name/DefaultModel/KeyEnv(/BaseURL); the doctrine: add/remove providers without recompiling.

Reason: separate repo isolates formula updates, and Homebrew's curl-based downloads bypass macOS Gatekeeper quarantine, making it the smoothest install path for macOS developers. The tap uses architecture-conditional URLs for prebuilt binaries from GitHub Releases. Future releases auto-update via the release workflow and a PAT (TAP\_PUSH\_TOKEN).

### Gotcha

<!-- lore:019fe7f2-f229-780e-8481-584142ebeb7e -->
* **bw get item fails after item creation without bw sync**: Trap: creating an item in Bitwarden web/app and immediately running \`bw get item \<name>\` fails because the CLI's local cache is stale. Fix: run \`bw sync\` first to update the cache, then the retrieval works. Without sync, the item won't appear, even if the vault is unlocked. This applies to any newly created Bitwarden item before first CLI retrieval.

<!-- lore:019fe7a5-4fe5-7b0e-bc77-c0b0af94e89e -->
* **eval.go supportedProviderKeyEnvs and conftest.py SUPPORTED\_PROVIDER\_KEYS must stay in sync**: Trap: adding a new provider key env var to only one list looks right because the change is local. Drift causes the no-key skip guard to miss a provider or the Python test helper to not recognize it. Fix: update both lists simultaneously — internal/cli/eval.go (supportedProviderKeyEnvs slice) and eval/conftest.py (SUPPORTED\_PROVIDER\_KEYS tuple). Include cross-reference comments in both files to surface the dependency for future maintainers.

<!-- lore:019fbf6b-0e14-7915-847a-5407c3fff771 -->
* **Gotcha: intentional eval gap preservation**: Trap: Treating all defects as interview practice looks right because it maximizes learning opportunities. Fix: Distinguish between foundational defects (fix now) and intentional eval gaps (preserve for evaluation). This prevents accidental implementation defects while maintaining deliberate evaluation targets.

<!-- lore:019fbe91-f026-79cc-aca6-5783c233e682 -->
* **Gotcha: starting from scratch**: Gotcha: starting from scratch. Trap: Assuming an existing codebase exists because the user wants a working chatbot. Fix: Create the entire repository structure and initial files from scratch, as the user doesn't have a repo currently. This prevents wasted effort on setup when the user needs to focus on implementation.

<!-- lore:019fc866-ca48-75b6-8fdb-eef9c050dd30 -->
* **MCP servers lazy-connected: 0/2 status is normal**: Trap: MCP status '0/2 servers' at session start looks like a config or auth failure. Fix: the gateway discovers configured servers and caches their tool metadata (playwright 24 tools, context-engine 6 tools) at session start; actual server processes spawn lazily on first use. Nothing had triggered a connection yet. Force it with mcp({connect: 'playwright'}) / mcp({connect: 'context-engine'}) or make a first tool call. Mode priority: action > tool (call) > connect > describe > search > server (list) > nothing (status). Tools are callable from cache even while connections are inactive, so 0/2 is NOT an error state.

<!-- lore:019fc866-ca5f-7234-aaf9-4d050d0cb074 -->
* **paths\_test.go self-match in no-hardcoded-user-paths scan**: Trap: a scan test asserting '/Users/forrestthomas/' and the old module path are absent from the repo matches its OWN source literals — failures look like leftover user paths but are the scanner itself. Same trap class: eval/tests/test\_harness\_config.py legitimately contains the path to assert its absence, so the Go scanner must exclude it. Fix: split the literal so it can't self-match (e.g. '/Users/forrestthomas' + '/'); an identical-string replacement is a silent no-op — break the concatenation instead. Silent no-op failures happen whenever the replacement string equals the original.

<!-- lore:019fc866-ca4e-775d-b9d7-954c5640ba59 -->
* **pi-run config-check/doctor false-fail under go run**: Trap: \`go run ./cmd/pi-run config-check\` (or doctor, providers) produces false failures or missing rows — looks like broken config. Fix: repoRoot() in internal/cli/setup.go derives the root from os.Executable(), which under \`go run\` is a temp-dir binary, so checks reading .pi/settings.json or providers.json resolve to the wrong directory. Always smoke-test from the built binary: \`go build -o bin/pi-run ./cmd/pi-run && ./bin/pi-run config-check\` from repo root. Under \`go test\` os.Executable() is likewise the test binary: compute root from runtime.Caller(0) (internal/cli sits 3 dirs below root) or set HARNESS\_ROOT.

<!-- lore:019fe7a1-e113-7b3c-b1d2-edfe49b7e155 -->
* **printf '%s' $@ concatenates args without spaces — dead negative assertion in test scripts**: Trap: using \`printf '%s' "$@"\` to record command-line arguments in a test script looks correct because it prints all arguments, but it concatenates them without any separator. Subsequent substring checks for standalone tokens (e.g., \`tests/\` as a bare argument) become dead code because the concatenated string contains no spaces or quotes. Fix: use \`printf '%s\n' "$@"\` to place each argument on its own line, or redirect each arg to a file with a separator, or use a language with list semantics. Otherwise, tests that rely on checking individual argument presence may silently pass despite missing expected args.

<!-- lore:019fc866-ca5b-7a14-8ef4-b0fb8e01e1fa -->
* **Subagent dispatch: add npm:pi-subagents to project .pi/settings.json**: Trap: Harness lacked subagent dispatch because project-level .pi/settings.json packages array did not include npm:pi-subagents. Pi's settings layering: project packages REPLACE user-level packages when a project settings file exists, causing pi-subagents (installed globally) to be omitted. Fix: add "npm:pi-subagents" to the packages array; durable config is .pi/settings.json, not .pi/npm/ (gitignored). After adding, new Pi sessions load the extension at startup. Verified with \`pi list\` showing 7 packages and subagent tools available.

<!-- lore:019fe7e8-09c5-76ec-be46-6c29f7c9bc3b -->
* **update-homebrew-formula.sh: macOS bash 3.2 doesn't support associative arrays**: Trap: using \`declare -A\` for SHA256 lookup looks right because it's a simple key-value mapping, but macOS ships bash 3.2 which does not support associative arrays (bash 4+ required). Fix: replace with a shell function \`sha\_of()\` that computes the SHA256 per asset using \`curl -sL\` and \`shasum -a 256\`, avoiding the need for an associative array altogether.

### Pattern

<!-- lore:019fe7f2-f22c-7938-92ca-18d27fb839f0 -->
* **Bitwarden fine-grained PAT storage as login item with username 'none'**: Store fine-grained personal access tokens (PATs) in Bitwarden as login items: set the item name to a descriptive identifier (e.g. PI\_HARNESS\_TAP\_PUSH), username to "none", and the token value as the password. This standard field structure enables consistent retrieval via \`bw get item \<name>\` and extraction of \`.login.password\` without structural guessing. Chose login items over secure notes because login items have a dedicated password field that maps directly to the token, simplifying retrieval scripts. The item can be placed in a folder like "Dev API Keys" for organization.

<!-- lore:019fe783-a527-786b-8ea0-eed46affb219 -->
* **CLI error format: pi-run: \<command>: \<reason> with stable exit codes**: All CLI errors follow the format \`pi-run: \<command>: \<reason>\` to stderr. Exit codes are stable: 0 OK, 1 generic, 2 usage, 3 missing key, 4 node/pi missing, 5 eval venv missing. Documented with \`--exit-codes\` flag. This ensures consistent, machine-parseable error handling. The format was chosen over unstructured error messages to simplify scripting and CI integration.
